# Auto Memory - 记忆漂移警告 (Memory Drift Caveat)

强调记忆可能过时，需要验证。

## 核心警告

**记忆是时间点观察，可能不再准确。**

## 记忆漂移的来源

1. **时间推移**
   - 项目 evolves
   - 决策改变
   - 优先级调整

2. **信息过时**
   - 用户角色可能改变
   - 技术栈可能更新
   - 外部系统可能迁移

3. **上下文丢失**
   - 原始决策的完整背景可能无法从记忆中恢复
   - 约束条件可能已经改变

## 如何处理记忆漂移

### 主动验证

当使用记忆指导决策时，考虑：

```
根据记忆，用户偏好 X...

但我应该验证：
- 这个偏好是否仍然有效？
- 是否有新的信息与此矛盾？
- 当前上下文是否适用这个规则？
```

### 更新记忆

当发现记忆过时时：

1. **更新记忆文件**
   - 修正错误信息
   - 添加新的上下文

2. **删除不再相关的记忆**
   - 如果某个记忆完全过时
   - 如果信息不再有用

3. **添加时间戳**
   - 对于项目记忆，保存绝对日期
   - 便于判断新鲜度

## 示例场景

### 场景 1: 过时的项目决策

```
记忆: "我们计划在 2024 Q1 迁移到新的数据库"

当前日期: 2024 Q3

应该: 询问用户这个迁移是否已经完成
```

### 场景 2: 用户偏好改变

```
记忆: "用户喜欢详细的解释"

但用户刚说: "请简洁一点"

应该: 优先使用当前指令，并更新记忆
```

### 场景 3: 技术栈更新

```
记忆: "项目使用 Webpack 构建"

但检查发现: 现在是 Vite

应该: 更新项目记忆以反映当前状态
```

## 记忆漂移 vs. 记忆腐化

| 概念 | 含义 | 处理 |
|------|------|------|
| **记忆漂移** | 记忆不再反映当前状态 | 验证和更新 |
| **记忆腐化** | 记忆本身包含错误信息 | 修正或删除 |

两者都需要主动管理，但处理方式略有不同。
