# Auto Memory - 信任回忆 (Trusting Recall)

如何正确使用和验证从记忆中召回的信息。

## 记忆召回原则

记忆是**时间点观察**，不是**实时状态**。你需要以适当的怀疑态度对待它们。

## 如何使用回忆的记忆

1. **将记忆视为线索，而不是事实**
   - 记忆提供了可能的上下文
   - 但不一定是当前的准确状态

2. **验证记忆的相关性**
   - 检查记忆是否与当前任务相关
   - 如果不确定，使用工具验证

3. **处理矛盾**
   - 如果记忆与当前观察矛盾，信任当前观察
   - 更新或删除过时的记忆

## 何时需要验证

以下情况你应该验证记忆：

- 记忆涉及具体的代码路径或文件位置
- 记忆提到的时间敏感信息（如截止日期、发布计划）
- 记忆与用户当前的陈述似乎矛盾

## 如何验证

```
如果记忆提到：
"项目使用 Jest 进行测试"

验证方法：
- 检查 package.json 中的 test 脚本
- 查找 jest.config.js 或类似文件
- 观察当前测试文件的实际格式
```

## 新鲜度考虑

### 记忆年龄

系统会根据文件的 `mtimeMs` 计算记忆年龄：

- 0 天: today
- 1 天: yesterday
- 2+ 天: N days ago

### 新鲜度提示

对于较旧的记忆，系统会附加新鲜度警告：

```
This memory is N days old. Memories are point-in-time observations, not live state...
```

这体现的是一种"软性汰换"策略：
- 保留旧记忆，避免知识直接丢失
- 通过提示降低系统对旧信息的盲目信任
- 把"是否仍然可信"交给后续消费链路综合判断

## 项目记忆的特殊考虑

项目记忆衰减很快，因为：
- 工作状态变化频繁
- 目标和优先级经常调整
- 团队成员和职责可能变动

所以对于项目记忆，特别要注意：
- 检查记忆是否仍然有效
- 如果不确定，询问用户确认
- 主动更新或删除过时的项目记忆
