# Auto Memory - 何时访问记忆

指导模型什么时候应该读取和使用记忆。

## 应该访问记忆的情况

### 1. 用户提及过去的互动

当用户说类似以下内容时：
- "像上次那样做"
- "还记得我们之前讨论的吗"
- "按照我之前告诉你的方式"

### 2. 用户提及之前保存的信息

- "查看我保存的关于...的记忆"
- "我之前让你记住..."

### 3. 重复或相关的任务

当当前任务与之前的工作相关时，应该检查记忆以获取上下文。

## 不需要访问记忆的情况

### 1. 纯代码问题

如果问题可以通过阅读当前代码库回答：
- "这个函数是做什么的？"
- "如何使用这个 API？"
- "这个文件在哪里？"

### 2. 通用编程问题

不涉及特定项目上下文的问题。

### 3. 全新的、无关的任务

用户开始一个全新的、与之前对话无关的任务。

## 访问记忆的顺序

1. **首先检查 `MEMORY.md`**
   - 获取可用记忆文件的索引
   - 了解有哪些主题类别

2. **然后读取相关主题文件**
   - 基于 `MEMORY.md` 中的描述选择相关文件
   - 不要一次性读取所有记忆文件

3. **相关性选择**
   - 使用 AI 模型选择最相关的记忆
   - 默认最多返回 5 个相关记忆

## 记忆与其他持久化机制的边界

| 机制 | 用途 | 何时使用 |
|------|------|----------|
| **Memory** | 长期用户偏好、项目上下文、反馈 | 跨会话持久化的上下文 |
| **Plan** | 当前任务的执行计划 | 复杂任务需要分步执行时 |
| **Tasks** | 具体的待办事项 | 需要跟踪的工作项 |
| **CLAUDE.md** | 项目文档、架构说明 | 代码库级别的文档 |

**不要混淆这些机制**:
- 不要把临时任务细节存入 memory
- 不要把代码文档存入 memory（应该去 CLAUDE.md）
- 不要把执行计划存入 memory（应该使用 Plan）
