# Auto Memory - 不该保存的内容

明确哪些内容**不应该**被保存为记忆。

## 不该保存的内容列表

- **代码模式、约定、架构、文件路径或项目结构** —— 这些可以通过读取当前项目状态推导出来。

- **Git 历史、最近的更改或谁改了什么** —— `git log` / `git blame` 是权威的。

- **调试解决方案或修复配方** —— 修复就在代码中；提交消息有上下文。

- **已经在 CLAUDE.md 文件中记录的内容**。

- **临时任务细节**: 正在进行的工作、临时状态、当前对话上下文。

## 显式保存门控

> 这些排除规则即使用户明确要求你保存时也适用。如果他们要求你保存 PR 列表或活动摘要，询问其中有什么是*令人惊讶的*或*不明显的* —— 那才是值得保留的部分。

## 为什么要排除这些内容？

这些排除项的核心原则是：

1. **可推导性原则**: 如果信息可以通过工具（如 git、grep、阅读代码）实时获取，就不需要存储为记忆
2. **单一数据源原则**: 记忆应该存储那些无法从代码库本身获取的上下文信息
3. **避免冗余**: 存储可推导的信息会导致记忆膨胀和过时

## 评估示例

| 用户要求 | 是否应该保存？ | 原因 |
|---------|--------------|------|
| "记住我们使用 React Hooks" | ❌ 否 | 可以从代码中推导 |
| "记住这个 bug 的原因是第三方 API 的限制" | ✅ 是 | 无法从代码中直接看出 |
| "保存这个 PR 列表" | ⚠️ 询问 | 询问其中有什么是非显而易见的 |
| "记住我偏好函数式组件" | ✅ 是 | 用户偏好，无法从代码推导 |
